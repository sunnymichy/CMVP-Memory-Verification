\subsection{Non-intrusiveness measurement}
\label{subsec:perturbation}
We quantify the cost of read-only observation on a live target that repeatedly performs a
deterministic AES known-answer computation while a separate, read-only monitor attaches by
PID and snapshots its committed regions (\code{perturbation\_bench.py}). We compare a
\emph{baseline} run (target alone) with a \emph{monitored} run (target plus monitor) over
\textbf{[XX]}\,s each.

\emph{Functional non-interference.} Across \textbf{[XX]} operations the target's output was
\emph{bit-identical} to the known answer in every case (\textbf{0} mismatches), in both the
baseline and monitored runs. Because the monitor issues no \code{WriteProcessMemory} and
maps nothing writable, the address-space data is unmodified by construction; the
zero-mismatch result confirms this end-to-end at the output level.

\emph{Resource and scheduling cost.} Table~\ref{tab:perturbation} reports the measured cost.
Observation reduces target throughput by \textbf{[XX]}\% (a consequence of brief
\code{NtSuspendProcess} pauses, not of any data modification), adds \textbf{[XX]} page faults
(reads paging in observed regions), and changes the working set by \textbf{[XX]}\,KB. Each
snapshot suspends the target for a mean of \textbf{[XX]}\,ms (p95 \textbf{[XX]}\,ms) while
reading \textbf{[XX]}\,MB. Consistent with the threat model (Section~\ref{subsec:principles}),
the perturbation is purely in \emph{scheduling} (\emph{when} threads run), bounded and
quantified here, while the address-space \emph{data} is provably preserved.
